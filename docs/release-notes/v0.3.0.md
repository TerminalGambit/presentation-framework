# v0.3.0 — Post-CD Response (2026-04-20)

v0.3 lands three audit-driven improvements on top of v0.2.1: a curated
**theme pack**, editable-PPTX **parity across every layout**, and a
feature-flagged **MAF integration spike**. No breaking YAML or MCP
changes; existing decks rebuild byte-identically under
`theme.preset: default`.

---

## Theme Pack — five named presets

One line to switch the full palette + font stack. All five pass the
existing WCAG-AA contrast checker; previews live under
[`docs/themes/`](../themes/) (1280×720 PNG per preset).

```yaml
theme:
  preset: editorial  # default | editorial | terminal | plex | nord
```

| Preset      | Palette                                         | Fonts                              |
|-------------|-------------------------------------------------|------------------------------------|
| `default`   | Dark navy + gold (pre-v0.3 tokens, unchanged)   | Playfair Display / Montserrat / Lato |
| `editorial` | Warm off-white + deep plum                      | Source Serif 4 / Inter             |
| `terminal`  | Near-black + GitHub-green accent                | JetBrains Mono (all slots)         |
| `plex`      | CD-interop neutral + indigo                     | IBM Plex Sans / IBM Plex Mono      |
| `nord`      | Cool slate + arctic blue                        | Inter / JetBrains Mono             |

Mix-and-match with per-key overrides (user keys win, dicts deep-merge):

```yaml
theme:
  preset: editorial
  accent: "#1F2937"   # override just the accent
```

Scaffold a new deck pre-wired to a preset:

```bash
pf init my-deck --theme nord
```

New MCP tool for agents:

```python
list_themes() -> list[{"name", "description", "screenshot_path"}]
```

## Editable PPTX parity (all 16 layouts)

`pf pptx --editable` now produces a deck where every slide has at
least one editable shape. The six layouts that previously fell back
to rasterized screenshots got native renderers:

- **`code`** — single mono text box; per-token color spans via optional
  Pygments (falls back to uncolored runs if Pygments isn't installed).
- **`toc`** — one editable text box per entry with a `NAMED_SLIDE`
  click_action hyperlink. Explicit `slide: N` in YAML wins; otherwise
  the nth entry maps to the nth section slide.
- **`chart`** — native python-pptx chart (double-click to edit data
  table). bar → `COLUMN_CLUSTERED` (Plotly parity), line / pie / donut
  / scatter / area mapped directly. Accent and secondary_accent paint
  series[0] and series[1]. Unknown types downgrade to an editable
  placeholder and surface as a `--strict` fallback.
- **`map`** — rasterized Leaflet map on the left, editable legend on
  the right with one text box per marker.
- **`mermaid`** — rasterized diagram plus the Mermaid source under a
  `--- mermaid source ---` separator in the speaker notes (so future
  tooling can regenerate).
- **`video`** — local mp4 paths embed via `add_movie`; remote URLs
  render a poster + "▶ Video: caption" hyperlink text box.

New `--strict` flag fails the build on any image fallback:

```bash
pf pptx --editable --strict -c examples/presentation.yaml
```

The file is still written so CI can attach it as an artifact. Per-
fallback reasons land on stderr.

See the manual-verification artifact
[`docs/plans/2026-04-20-pptx-editable-verification.md`](../plans/2026-04-20-pptx-editable-verification.md)
for the per-layout shape inventory and the Jack-checklist for the
PowerPoint manual pass.

## MAF integration spike (experimental)

A flag-gated, contract-frozen spike for integrating
[MAF](https://github.com/) as a subprocess video renderer. Off by
default — opt-in via:

```yaml
theme:
  experimental:
    maf_video: true

slides:
  - layout: video-maf
    data:
      manifest_path: animations/explainer.maf.yaml
      poster: animations/explainer-poster.png
      caption: "How the scheduler preempts"
```

Behavior summary:

- **Flag off** → layout renders the poster as a static still; no
  subprocess spawned, no behavioral change from pre-v0.3.
- **Flag on + `maf` on PATH** → shells out to
  `maf render <manifest> --quiet --json --out <dir>`, caches the
  result under `.pf-cache/maf/<sha256>/`, and embeds the mp4 + vtt
  in the slide.
- **Flag on + `maf` missing** → build warning, poster fallback,
  exit 0. `pf pptx --strict` promotes this to a fallback event.
- **Second build against the same manifest** → cache hit; no
  subprocess call.

The **full interface is frozen** in
[`docs/maf-integration-contract.md`](../maf-integration-contract.md) —
YAML fields, subprocess argv, stdout JSON schema, cache-key formula,
degradation matrix, and explicit non-goals per SPEC §7.4. Downstream
tasks and the real-binary integration in a future release will work
against this contract without contract changes.

## Under the hood

- `_pptx_theme` now exposes `font_mono` and `secondary_accent` to
  every native renderer.
- `export_pptx_editable` returns a list of fallback events (empty
  list = happy path). The dispatch loop uses `inspect.signature` to
  pass context kwargs (`prs`, `slides_cfg`, `slide_index`,
  `slide_file`, `pw_context`, `fallbacks`) only to renderers that
  declare them — the other ten renderers stay on their existing
  `(slide, data, theme)` signature.
- A two-pass build in `export_pptx_editable` (create all slides,
  then render) lets `_render_toc` target forward-indexed slides via
  `prs.slides[N]` instead of racing the add_slide loop.
- `_render_chart` maps `bar` → `COLUMN_CLUSTERED` for Plotly visual
  parity (Plotly's default bar is vertical, python-pptx's
  `BAR_CLUSTERED` is horizontal). Use `chart_type: bar-horizontal`
  if you actually want horizontal bars.
- The theme preset loader deep-merges user overrides into the
  preset's token set; scalars replace, dicts merge recursively
  (D3 precedence rule, documented in CLAUDE.md #9).
- Light-theme typography variables are now emitted by both branches
  of `generate_variables_css` — a pre-existing bug surfaced by T1.10's
  parametrized tests.

## Compatibility

- No breaking changes to YAML keys or MCP tool signatures.
- New keys are all additive: `theme.preset`, `theme.experimental`,
  `slide.data` fields for `video-maf`.
- `pf init` now defaults to scaffolding with `theme: {preset: default}`
  instead of the inline color block — identical visual output, but
  decks scaffolded on v0.3+ are one line shorter.

## Upgrade notes

For existing deck maintainers:

1. No required action — existing `theme.primary`/`accent` YAML keeps
   working.
2. To adopt a preset, add `theme.preset: <name>` at the top of the
   theme block and drop whatever it replaces. Run `pf build` and
   eyeball the result.
3. To exercise the MAF spike, set
   `theme.experimental.maf_video: true` and install `maf` on PATH.
   Without `maf` the slide renders a poster fallback — safe to land.

For MCP consumers:

- `list_themes()` is new; the existing five tools are unchanged.
- `list_layouts()` now includes `video-maf` in the enumeration (17
  layouts total).
